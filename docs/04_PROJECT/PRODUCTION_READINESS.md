# Purpose

To record what "production-ready" means for this platform as of `F11-S01` (see `docs/04_PROJECT/DECISION_LOG.md#cto-080`) — what was already in place from earlier sprints, what was added this sprint, and why. This is a reference document, not a standard with its own approval process.

# What Was Already Production-Ready

Several of this sprint's TASKS review items were already solid, built incrementally across `F5`–`F8` and left unchanged here:

- **Structured logging** (`packages/shared/src/logger.ts`): every log line is a single JSON object (`timestamp`, `level`, `message`, plus arbitrary context like `correlationId`) written to stdout/stderr by level — ready for any log aggregator to ingest without a custom parser.
- **Correlation IDs** (`apps/api/src/shared/middleware/correlation-id.middleware.ts`): every request gets a correlation id (incoming `X-Correlation-Id` header honored, otherwise generated), echoed back on the response and attached to every log line for that request — request tracing across a distributed log stream works out of the box.
- **Standardized error handling** (`apps/api/src/shared/filters/global-exception.filter.ts`): every unhandled exception, `HttpException` or not, is caught once and mapped to a single `ApiErrorResponse` shape (`{ success: false, error: { code, message, correlationId } }`). Non-`HttpException` errors never leak their message or stack to the client — always "Internal server error" — while the real error is still logged server-side with full context.
- **Health checks** (`F5-S01`): `GET /health` (liveness, no dependency checks — "is the process alive"), `GET /health/live` (same), `GET /health/ready` (checks Database/Redis/Object Storage/Workflow Runtime connectivity, returns HTTP 503 if anything is down) — the standard liveness/readiness split an orchestrator expects.
- **Graceful shutdown**: `app.enableShutdownHooks()` (`main.ts`) plus `DatabaseModule.onApplicationShutdown` (`apps/api/src/infrastructure/database/database.module.ts`) disconnecting Prisma on `SIGTERM`/`SIGINT` — in-flight requests are allowed to finish and the database connection is closed cleanly rather than dropped mid-transaction. Redis has no client of its own yet (only a TCP-reachability health check, `F5-S01`), so there is nothing further to close there.
- **API documentation**: Swagger/OpenAPI at `GET /docs` (`F8-S03`, `CTO-076`), reflecting live routes and DTOs.
- **Secrets externalized**: every credential has always been env-var driven (`packages/config`, `.env.example`) — this sprint only changed what happens when a production secret is *missing*, not how secrets are supplied.

# What This Sprint Added

**Secure defaults, enforced only where the risk actually is**: `packages/config`'s local-development defaults (`POSTGRES_PASSWORD=postgres`, `MINIO_ROOT_PASSWORD=minioadmin`, etc.) are convenient for zero-setup local development and stay unchanged — the risk isn't that they exist, it's a production deploy silently running on them. `assertProductionSecrets(config)` (`packages/config/src/index.ts`) throws a clear, actionable error listing exactly which of `DATABASE_URL`/`POSTGRES_PASSWORD`/`MINIO_ROOT_USER`/`MINIO_ROOT_PASSWORD` are missing whenever `NODE_ENV=production`. **It is called explicitly from `apps/api/src/main.ts`'s `bootstrap()`, not from inside `loadConfig()` itself** — `loadConfig()` is shared by `apps/web` too, and `next start` always sets `NODE_ENV=production` for the web app regardless of environment; the web app has no Postgres/MinIO credentials of its own and would have been wrongly blocked from starting if the check lived in the shared loader. This was caught live: the first version of this change broke `apps/web`'s `next start`, fixed by moving the assertion to the one app that actually owns those secrets.

**Validation**: no request body was runtime-validated anywhere before this sprint — every DTO (`CreateClientDto`, `CreateAuditDto`, `TransitionCampaignStatusDto`, `TransitionActionStatusDto`, `TransitionCycleStatusDto`, `AskConsultantDto`, `CreateOptimizationCycleDto`, `SetProjectBaselineDto`) was a plain class with compile-time-only field types; a malformed or missing field would either silently pass through as `undefined` or surface as a confusing error several layers deeper. Every DTO now carries `class-validator` decorators (`@IsString()`/`@IsNotEmpty()`/`@IsOptional()`), and `main.ts` registers a global `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })`. This is deliberately a *shape* validation layer only — "is this field present and the right primitive type" — not a duplicate of business-rule validation that already exists deeper in the stack (e.g. `AuditUrlVO` already validates that `url` is a real, parseable URL; every status-transition endpoint already whitelists its own valid status values in the controller). Standardizing shape validation catches malformed requests earlier and more consistently without touching or duplicating any existing business rule.

**CORS**: `app.enableCors({ origin: config.CORS_ORIGIN.split(',') })` — previously unconfigured (Nest/Express send no CORS headers unless told to, which already blocked cross-origin browser requests by default, but left the API's actual policy implicit rather than deliberate). `CORS_ORIGIN` defaults to `http://localhost:3000`. Note this has no effect on the Next.js app's own calls to the API — `apps/web`'s Server Actions (`apps/web/app/actions.ts`) call the API server-to-server via Node's `fetch`, which is never subject to browser CORS enforcement; `CORS_ORIGIN` only governs a browser making a direct cross-origin request to the API (e.g. a future separate client, or the Swagger "Try it out" button if ever hosted off-origin).

**Compression**: `app.use(compression())` — gzips responses above the `compression` package's default 1KB threshold (verified live: a 7.6KB `/docs-json` response came back with `Content-Encoding: gzip`; small responses like an empty `/clients` list correctly stay uncompressed, since compressing a few bytes only adds overhead).

**Security headers**: `app.use(helmet())` — verified live: `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Strict-Transport-Security`, `Referrer-Policy: no-referrer`, `X-DNS-Prefetch-Control: off` all present on every response, using helmet's defaults (no custom CSP was written — this platform serves JSON and Swagger's own UI, not a first-party HTML frontend from this origin, so a bespoke Content-Security-Policy wasn't judged necessary this sprint).

**Rate limiting**: `@nestjs/throttler`'s `ThrottlerModule.forRoot([{ name: 'default', ttl: RATE_LIMIT_TTL_MS, limit: RATE_LIMIT_LIMIT }])` plus a global `APP_GUARD` (`apps/api/src/app.module.ts`), defaulting to 120 requests per 60-second sliding window per client IP (`trust proxy` is enabled so this reads the real client IP behind a reverse proxy, not the proxy's). Verified live: the 120th request within a window returns HTTP 429, and the limit resets after the window. `HealthController` is annotated `@SkipThrottle()` — orchestrator liveness/readiness probes are typically polled every few seconds and must never be throttled, or a busy API could cause a healthy instance to be killed for looking unhealthy.

**Timeouts**: a new `TimeoutInterceptor` (`apps/api/src/shared/interceptors/timeout.interceptor.ts`), registered globally alongside the existing `LoggingInterceptor`, aborts any request still running after `REQUEST_TIMEOUT_MS` (default 30s) with HTTP 408, so a single slow downstream dependency can never hold a request open indefinitely.

**Log verbosity is now configurable**: `packages/shared/src/logger.ts` gained `setLogLevel`, called once at bootstrap from `LOG_LEVEL` (or a `NODE_ENV`-based default — `info` in production, `debug` otherwise). Below-threshold calls are now no-ops rather than always writing every `debug` line, reducing log volume/cost in production without touching any call site.

**Development artifacts removed**: the seven unfilled root-level "Forge" scaffolding templates (`ARCHITECTURE.md`, `CHANGELOG.md`, `CURRENT_STATE.md`, `DECISION_LOG.md`, `NEXT_SPRINT.md`, `PROJECT_BLUEPRINT.md`, `RETROSPECTIVE.md` — never filled in, superseded entirely by the real, actively-maintained equivalents in `docs/04_PROJECT/`) and the empty scaffolding directories (`backend/`, `frontend/`, `infrastructure/{database,cache,storage}/.gitkeep`, `scripts/{development,release}/.gitkeep` — superseded by `docker/docker-compose.yml` and `scripts/start-alpha.sh`) identified as unused by the `F8` Local Development Access Report were deleted. Nothing here was ever real project content; git history preserves it if ever needed.

# Rejected Scope

- **Docker images / a production Dockerfile / CI-CD pipeline / infrastructure-as-code.** This ticket's TASKS list is entirely about the *application's own* runtime behavior (config, logging, error handling, validation, CORS, compression, headers, rate limiting, timeouts, health checks, shutdown) — none of it asks for a deployment platform, and this repository has never had one (`docker/docker-compose.yml` is a local-dev convenience only, per `CTO-076`). Out of scope, and a substantially different kind of work.
- **A custom Content-Security-Policy.** `helmet()`'s defaults were judged sufficient — this API has no first-party HTML views of its own to protect against XSS (Swagger's UI is the one exception, and disabling helmet's CSP for it specifically was considered but not needed since nothing in this sprint reported a Swagger UI breakage).
- **A Redis client / cache layer.** Redis has existed only as a health-checked TCP dependency since `F5-S01`, never actually used by any business logic — production-hardening an unused connection would be speculative work with no current caller.
- **Authentication/authorization.** Still explicitly out of scope, consistent with every prior sprint (`CTO-075`, README's "Demo Users" section) — "implement production-ready defaults... without changing business behavior" does not license adding a new capability this platform has never had.
